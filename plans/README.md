## Findings considered and rejected

- Treat the phone's current browser viewport as the capture viewport: rejected because it would make historical images depend on whichever device opens the viewer; explicit saved viewport profiles keep comparisons repeatable.
- Automatically discover framework components from source code: rejected for this plan because Rewindry is framework-neutral and component screenshots need an app-provided deterministic route/state and stable DOM selector.
- Backfill old missing screenshots from current source: rejected because current files and browser state cannot prove what those earlier iterations rendered. Plan 002 separately handles explicitly acknowledged replays from each checkpoint's own saved source and labels them as reconstructed.
